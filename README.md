# システム仕様書：ショートカットキー学習ダンジョンゲーム

## 1\. プロジェクト概要 \& コンセプト

* **タイトル（仮）**: ショートカット・ダンジョン（Shortcut Dungeon）
* **コンセプト**: パソコン初心者がゲームを楽しみながらショートカットキー（Ctrl+C, Ctrl+V, Alt+Tabなど）を学べる学習体験型2Dアクション・パズル。
* **プラットフォーム**: PC（Windowsメイン、後日Mac対応を考慮してキー割り当ては拡張可能にする）
* **推奨開発スタック**: HTML5 / JavaScript (ES6+) / HTML5 Canvas API（外部ライブラリなし、またはPhaser.js）

  * ビルドツールとしてViteを使用する（ゲーム・ステージエディタ共通）。
  * VS Codeで開発し、`npm run dev` でブラウザ実行する構成とする。

\---

## 2\. ゲームシステム \& ルール

### 画面構成

* **2D トップダウン（見下ろし型）** / 1画面固定カメラ。

### コアゲームループ

1. **ステート選択**: タイトル画面 → ステージセレクト画面
2. **ダンジョンパート**:

   * プレイヤーはキーボード操作で1画面ダンジョン内を移動。
   * キーボードのショートカットキー操作を使ってギミックを解く・アイテムを獲得する。
   * ゴールに到達すると次のステージへ。
3. **ボスパート**:

   * 数ステージクリアごとにボス戦が発生。
   * ボスからショートカットキーに関する「クイズ」が出題される。
   * 規定回数正解するとボス討伐完了 → リザルト画面へ。

### 操作方法

* **基本移動**: 矢印キー (Arrow Keys) または WASD キー
* **アクション / ギミック操作**: 対象のショートカットキー（例: Ctrl+C, Ctrl+V, Ctrl+Z 等）
* **UI操作**: マウス / キーボード

### 判定・ゲームオーバー・勝利条件

* **勝利条件**: ステージのゴール到達、およびボス戦のクイズ全問正解。
* **敗北条件**: HP（ライフ）が0になる、クイズの誤答数が上限に達する、または木箱なしでマグマに入る。
* **ゲームオーバー後**: `R` または `Enter` で現在のステージに再挑戦（HP・スキル・アイテムを初期化）。

## 3\. データ構造 \& エンティティ設計

### プレイヤー (Player)

* `x`, `y`: グリッド位置または座標
* `hp`: 現在のライフ（初期値: 3）
* `maxHp`: 最大ライフ
* `skillEnergy`: ショートカットスキル使用可能回数
* `inventory`: 所持アイテムリスト

### アイテム (Items)

* `LifePotion`: HP（残機）を1回復。
* `SkillPotion`: ショートカットスキルの残り使用回数を回復。

### クイズデータ (Quiz)

* `id`: クイズID
* `question`: 問題文（例: 「選択したファイルをコピーするショートカットは？」）
* `correctInput`: 正解のキー入力（例: `\['Control', 'c']`）
* `options`: 4択の場合の選択肢文字列リスト

## 4\. 画面構成 \& UI仕様

1. **タイトル画面 (TitleScene)**

   * ゲームタイトル、スタートボタン、キーボード操作説明ボタン。
2. **ステージセレクト画面 (StageSelectScene)**

   * クリア済みのステージと解放中のステージ選択。
3. **ゲームメイン画面 (MainGameScene)**

   * 1画面のダンジョンマップ（マップ、壁、障害物、宝箱、ゴール）。
   * **UI領域**:

     * ライフ表示（ハートアイコン等）
     * スキル残り使用回数ゲージ/数値
     * インベントリ UI（獲得したアイテム一覧）
     * 現在のショートカットガイド（初心者向けヘルプ表示）
4. **ボス・クイズ画面 (BossQuizScene)**

   * ボスのスプライトとダイアログボックス。
   * クイズ問題文とキー入力受付インジケーター（または選択肢ボタン）。
5. **ポーズ画面 (PauseModal)**

   * ESCキーで呼び出し。音量設定、リトライ、タイトルへ戻る。
6. **リザルト画面 (ResultScene)**

   * クリアタイム、クイズ正解率、スコア表示。

## 5\. コーディング規約 \& 設計方針（Copilotへの指示）

Copilotがコードを生成・補完する際は、以下のルールを厳守してください：

1. **モジュール化とクラス設計**:

   * シーン管理（`SceneManager`）、入力管理（`InputHandler`）、オーディオ管理（`AudioManager`）を独立したモジュール/クラスとして設計すること。
2. **キー入力判定**:

   * `keydown` イベントで `event.ctrlKey` や `event.key` を正確にチェックし、ブラウザのデフォルト挙動（例: Ctrl+Sの保存ダイアログ、Ctrl+Pの印刷ダイアログ）を `event.preventDefault()` で正しく無効化すること。
3. **Mac対応への配慮**:

   * 将来的に Windows の `Control` を Mac の `Command` (Meta) に差し替えられるよう、キーボード入力の抽象化レイヤーを作成すること。
4. **コードの生成単位**:

   * 一度に巨大なファイルを生成せず、まずはクラス図やファイル構成を提示した上で、1ファイルずつ完結したクリーンなコードを出力すること。

## 6\. 開発環境

### 必要環境

* Node.js 22 以上
* npm

### コマンド（ゲーム）

```bash
npm install       # 初回のみ
npm run dev       # 開発サーバー
npm run build     # ステージ検証 + 本番ビルド（dist/）
npm run validate:stages
npm test
```

### コマンド（ステージエディタ）

```bash
cd editor
npm install       # 初回のみ
npm run dev       # エディタの開発サーバー
npm run build     # editor/dist/ に出力
```

### 主要ディレクトリ

* `src/data/stages/` … ステージJSONの置き場。ここに置くだけでビルド時に自動検出される
* `packages/stage-schema/` … ステージ仕様・バリデーション（ゲーム、エディタ、CIで共用）
* `editor/` … ステージエディタ（ゲームとは独立したViteアプリ）
* `scripts/validate-stages.mjs` … 全ステージJSONの検証
* `docs/stage-editor-design.md` … エディタと自動取り込みの設計書

## 7\. ステージ追加手順

### 7.1 エディタで作成する

1. `editor` で `npm run dev` を起動し、表示されたURLを開く
2. ツールを選び、キャンバスへ壁・開始位置・ゴール・木箱・アイテムなどを配置する
3. 右パネルに検証エラーがないことを確認する
4. `JSONを保存` を押し、`{id}.json` をダウンロードする

### 7.2 リポジトリへ追加する

1. ダウンロードしたJSONを `src/data/stages/` に置く
2. `git add src/data/stages/<id>.json`
3. コミットして `main` へpushする
4. Cloudflareが自動でビルドし、`number` の順にステージが追加される

`src/data/stages.js` やゲーム本体のコードを編集する必要はない。

### 7.3 ステージJSONのルール

* ファイル名は `{id}.json`。`id` は作成後に変更しない
* 配置可能範囲は `x: 1〜22`, `y: 1〜14`（外周1マスは固定の壁）
* `number` は1以上で全ステージ内で一意。進行順になる
* `goalBlock` と `shortcutGate` は不要なら `null`
* 壁は `obstacles` の矩形で保存される（エディタが自動変換）
* 木箱は `kind` で種類を指定する。`"normal"` はノーマル木箱、`"colored"` は色つき木箱
* 色つき木箱を同じ色の `colorSwitches` にペーストすると、同色の `colorWalls` が開く
* `colorSwitches` / `colorWalls` は不要なら空配列 `[]`
* `lasers` は `{ x, y, direction, length }`。`direction` は `up` / `down` / `left` / `right`。ノーマル木箱で遮ると5秒間ビームが止まり、時間切れで木箱が壊れる。色つき木箱では遮れない
* `magma` は `{ x, y }` の配列。木箱がないマグマに入るとゲームオーバー。ノーマル木箱を置いたマグマのマスだけ渡れる
* `lasers` / `magma` は不要なら空配列 `[]`
* 仕様の詳細は `docs/stage-editor-design.md` を参照

### 7.4 Cloudflare Pagesの設定

| プロジェクト | Root directory | Build command | Output directory |
|---|---|---|---|
| ゲーム | `/` | `npm ci && npm run build` | `dist` |
| エディタ | `editor` | `npm ci && npm run build` | `dist` |

ゲームのビルドでは `npm run build` の前に全ステージJSONが検証される。不正なステージがあるとビルドは失敗し、本番へデプロイされない。
